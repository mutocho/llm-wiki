# 적재 라우팅 규칙

새 지식을 적재할 때 어느 허브에 넣을지 판단하는 규칙. 모든 페이지 frontmatter에 `topics:`를 반드시 기입한다.

## 판단 기준

| 내용 | topics | 위치 |
|---|---|---|
| DB 기술 지식, 트러블슈팅, 런북, 쿼리/스크립트 | `[dba]` | `dba/` |
| 내가 수행한 업무의 기록, 성과, 임팩트 — 사소한 설정 변경 등 회사에서 수행한 모든 작업 포함 | `[career]` | `career/<회사>/` (아래 회사 라우팅 참조) |
| 업무로 수행한 DBA 작업 (예: 장애 대응, 마이그레이션 수행) | `[dba, career]` | 기술 내용은 `dba/`에, 업무 기록은 `career/<회사>/`에 각각 페이지 생성 후 상호 `[[링크]]` |
| 개인 일정·할 일·계획 — 약속, 예약, 마감일, 반복 일정, 개인 프로젝트 계획 | `[personal]` | `personal/` |

## career 회사 라우팅

`career/`는 회사 단위 하위 폴더로 적재한다. 회사명은 별도로 입력받지 않고 다음 규칙으로 자동 판단한다:

- **현재 회사는 카카오게임즈** — 회사가 명시되지 않은 업무 기록은 `career/kakaogames/`에 적재
- 회사를 특정할 수 없는 기록(회사 무관 커리어 자료, 어느 재직 시기인지 불분명한 것)은 `career/common/`에 적재
- 이직 시 이 문단의 현재 회사만 갱신하고 새 폴더를 추가한다

## personal 적재 규칙

개인 일정 관리용 허브. 업무 지식이 아닌 "나의 시간"에 관한 것을 적재한다.

- 날짜가 있는 일정은 페이지 frontmatter에 `due: <ISO날짜>`를 기입하고, 상대 날짜("다음 주 금요일")는 절대 날짜로 변환해 기록
- 단발성 할 일 여러 개는 페이지를 남발하지 않고 `personal/todo.md` 한 페이지에 체크박스로 누적
- 반복 일정·개인 프로젝트 계획은 건별 페이지로 생성
- 업무 일정이더라도 지식이 아닌 순수 일정(회의 약속 등)이면 `personal/`에 적재

## 양쪽 적재 원칙

하나의 사건이 양쪽에 해당하면 **한 페이지에 섞지 않는다**:

1. `dba/` 페이지 — 재사용 가능한 기술 지식만 (회사 맥락 최소화)
2. `career/` 페이지 — 언제, 왜, 내가 무엇을 했고, 임팩트가 무엇인지
3. 두 페이지를 `[[wikilink]]`로 상호 연결

이렇게 하면 `dba/`는 이직 후에도 쓸 수 있는 지식베이스가 되고, `career/`는 그대로 성과 정리·포트폴리오 원천이 된다.

## 민감정보

계정, 비밀번호, 토큰, 내부 IP, 고객 데이터는 어느 페이지에도 기록하지 않는다. 필요하면 위치만 참조로 남긴다 (예: "자격증명은 사내 vault 참조").
