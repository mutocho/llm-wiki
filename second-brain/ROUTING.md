# 적재 라우팅 규칙

새 지식을 적재할 때 어느 허브에 넣을지 판단하는 규칙. 모든 페이지 frontmatter에 `topics:`를 반드시 기입한다.

## 판단 기준

| 내용 | topics | 위치 |
|---|---|---|
| DB 기술 지식, 트러블슈팅, 런북, 쿼리/스크립트 | `[dba]` | `dba/` |
| 내가 수행한 업무의 기록, 성과, 임팩트 | `[career]` | `career/` |
| 업무로 수행한 DBA 작업 (예: 장애 대응, 마이그레이션 수행) | `[dba, career]` | 기술 내용은 `dba/`에, 업무 기록은 `career/`에 각각 페이지 생성 후 상호 `[[링크]]` |

## 양쪽 적재 원칙

하나의 사건이 양쪽에 해당하면 **한 페이지에 섞지 않는다**:

1. `dba/` 페이지 — 재사용 가능한 기술 지식만 (회사 맥락 최소화)
2. `career/` 페이지 — 언제, 왜, 내가 무엇을 했고, 임팩트가 무엇인지
3. 두 페이지를 `[[wikilink]]`로 상호 연결

이렇게 하면 `dba/`는 이직 후에도 쓸 수 있는 지식베이스가 되고, `career/`는 그대로 성과 정리·포트폴리오 원천이 된다.

## 민감정보

계정, 비밀번호, 토큰, 내부 IP, 고객 데이터는 어느 페이지에도 기록하지 않는다. 필요하면 위치만 참조로 남긴다 (예: "자격증명은 사내 vault 참조").
